<details>
<summary>Đáp án câu 1</summary>

**B.** `await` không tạo thread mới, và với I/O thật thì trong lúc chờ không có thread nào bị giữ. Khi dữ liệu về, một thread bất kỳ của pool chạy tiếp. Đó là toàn bộ lý do async tăng thông lượng ([bài 6.1](6.1-why-async-matters.md), [bài 6.2](6.2-task-and-async-await.md)).

</details>

</details>

**Câu 3.** Cùng một dòng `var data = GetDataAsync().Result;`. Câu nào đúng?

#### Bài 1 — Chuyển `CustomerSyncService` sang async (Dễ, 25 điểm)

Cho service đồng bộ sau:

```csharp
// TRƯỚC — đồng bộ, giam thread trong lúc chờ database
public class CustomerSyncService(CrmDbContext db)
{
    public Customer? GetById(int id)
        => db.Customers.FirstOrDefault(c => c.Id == id);

    public List<Customer> GetActive()
        => db.Customers.Where(c => c.IsActive).ToList();

    public void UpdateLastContact(int id, DateTime contactDate)
    {
        var customer = db.Customers.Find(id);
        if (customer is null) return;
        customer.LastContactDate = contactDate;
        db.SaveChanges();
    }
}
```

Yêu cầu:

1. Viết `CustomerService` với `GetByIdAsync`, `GetActiveAsync`, `UpdateLastContactAsync`, dùng `FirstOrDefaultAsync`, `ToListAsync`, `FindAsync`, `SaveChangesAsync`.
2. Mỗi phương thức nhận `CancellationToken ct = default` làm tham số cuối và truyền nó xuống mọi lời gọi EF Core.
3. `UpdateLastContactAsync` trả về `bool`: `false` nếu không có khách hàng.
4. Viết test bằng SQLite trong bộ nhớ: một test cho kết quả đúng, một test chứng minh token **đã huỷ** làm phương thức ném `OperationCanceledException`, một test chứng minh khi huỷ thì **không có gì được lưu**.

**Tiêu chí chấm:**

| Tiêu chí | Điểm |
|---|---|
| Ba phương thức async đúng tên, đúng kiểu trả về, không còn lời gọi EF Core đồng bộ nào | 8 |
| `CancellationToken` là tham số cuối và được truyền vào **mọi** lời gọi EF Core | 6 |
| Không có `.Result`, `.Wait()`, `async void` | 3 |
| Test dùng SQLite trong bộ nhớ, có test huỷ (`ThrowsAnyAsync<OperationCanceledException>`) và test "không lưu khi huỷ", `dotnet test` xanh | 8 |

`Crm.Lab/Customers.cs`:

```csharp
using Microsoft.EntityFrameworkCore;

namespace Crm.Lab;

public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
    public bool IsActive { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? LastContactDate { get; set; }
}

public class CrmDbContext(DbContextOptions<CrmDbContext> options) : DbContext(options)
{
    public DbSet<Customer> Customers => Set<Customer>();
}

// Bài 1 — bản async của CustomerSyncService
public class CustomerService(CrmDbContext db)
{
    public Task<Customer?> GetByIdAsync(int id, CancellationToken ct = default)
        => db.Customers.FirstOrDefaultAsync(c => c.Id == id, ct);

    public Task<List<Customer>> GetActiveAsync(CancellationToken ct = default)
        => db.Customers.Where(c => c.IsActive).ToListAsync(ct);

    // Trả về false nếu không có khách hàng, thay cho "return" im lặng của bản cũ
    public async Task<bool> UpdateLastContactAsync(int id, DateTime contactDate, CancellationToken ct = default)
    {
        var customer = await db.Customers.FindAsync([id], ct);
        if (customer is null) return false;

        customer.LastContactDate = contactDate;
        await db.SaveChangesAsync(ct);
        return true;
    }
}
```

`Crm.Lab.Tests/LabTests.cs`, phần chung và test của bài 1:

```csharp
using System.Diagnostics;
using Crm.Lab;
using Microsoft.Data.Sqlite;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Logging.Abstractions;

namespace Crm.Lab.Tests;

// Database SQLite trong bộ nhớ: sống chừng nào connection còn mở
public sealed class SqliteFixture : IDisposable
{
    private readonly SqliteConnection _connection = new("Data Source=:memory:");
    public CrmDbContext Db { get; }

    public SqliteFixture()
    {
        _connection.Open();
        Db = new CrmDbContext(new DbContextOptionsBuilder<CrmDbContext>().UseSqlite(_connection).Options);
        Db.Database.EnsureCreated();
        Db.Customers.AddRange(
            new Customer { Name = "An", Email = "an@example.com", IsActive = true, CreatedAt = new DateTime(2026, 1, 10) },
            new Customer { Name = "Bình", Email = "binh@example.com", IsActive = false, CreatedAt = new DateTime(2026, 2, 5) },
            new Customer { Name = "Chi, Lê", Email = "chi@example.com", IsActive = true, CreatedAt = new DateTime(2026, 3, 1) });
        Db.SaveChanges();
        Db.ChangeTracker.Clear();
    }

    public void Dispose() { Db.Dispose(); _connection.Dispose(); }
}

public class CustomerServiceTests
{
    [Fact]
    public async Task GetActiveAsync_ReturnsOnlyActive()
    {
        using var f = new SqliteFixture();
        var result = await new CustomerService(f.Db).GetActiveAsync();
        Assert.Equal(2, result.Count);
    }

    [Fact]
    public async Task GetActiveAsync_CancelledToken_Throws()
    {
        using var f = new SqliteFixture();
        using var cts = new CancellationTokenSource();
        cts.Cancel();
        await Assert.ThrowsAnyAsync<OperationCanceledException>(() => new CustomerService(f.Db).GetActiveAsync(cts.Token));
    }

    [Fact]
    public async Task UpdateLastContactAsync_CancelledToken_DoesNotSave()
    {
        using var f = new SqliteFixture();
        using var cts = new CancellationTokenSource();
        cts.Cancel();

        await Assert.ThrowsAnyAsync<OperationCanceledException>(
            () => new CustomerService(f.Db).UpdateLastContactAsync(1, new DateTime(2026, 9, 1), cts.Token));

        f.Db.ChangeTracker.Clear();
        Assert.Null((await f.Db.Customers.FindAsync(1))!.LastContactDate);
    }

    [Fact]
    public async Task UpdateLastContactAsync_UnknownId_ReturnsFalse()
    {
        using var f = new SqliteFixture();
        Assert.False(await new CustomerService(f.Db).UpdateLastContactAsync(999, DateTime.UtcNow));
    }
}
```

1. **SQLite `:memory:` chỉ sống khi connection còn mở**, nên fixture tự mở một `SqliteConnection` và truyền nó cho `UseSqlite`. Mỗi test tạo fixture riêng, dữ liệu không dính sang nhau.
2. **`ThrowsAnyAsync` chứ không phải `ThrowsAsync`.** EF Core có thể ném `TaskCanceledException` (lớp con của `OperationCanceledException`); `ThrowsAnyAsync` chấp nhận cả lớp con.
3. **Test "không lưu khi huỷ"** gọi `ChangeTracker.Clear()` trước khi đọc lại, để chắc chắn giá trị đọc từ database chứ không phải từ bộ nhớ của context.

#### Bài 2 — Gửi thông báo qua ba kênh song song, có hạn chung (Trung bình, 30 điểm)

Viết `CustomerNotificationService` nhận danh sách `INotifier` (email, SMS, push) qua constructor:

```csharp
public interface INotifier
{
    string Channel { get; }
    Task SendAsync(int customerId, string message, CancellationToken ct);
}
```

`SendToAllChannelsAsync(int customerId, string message, CancellationToken ct = default)` phải:

1. Gửi qua mọi kênh **song song** bằng `Task.WhenAll`.
2. Áp hạn chung (mặc định 5 giây, cho phép truyền vào constructor để test) bằng `CreateLinkedTokenSource` nối token của bên gọi với token hết hạn.
3. Kênh nào lỗi hoặc quá hạn thì **ghi log và tính là thất bại**, không làm hỏng các kênh khác.
4. Nếu **bên gọi** huỷ thì **ném** `OperationCanceledException`, không trả về một con số trông như hợp lệ.
5. Trả về số kênh gửi thành công.

**Tiêu chí chấm:**

| Tiêu chí | Điểm |
|---|---|
| Các kênh chạy song song (tổng thời gian khoảng bằng kênh chậm nhất hoặc bằng hạn, không phải tổng) | 6 |
| Hạn chung dùng `CreateLinkedTokenSource`, cả hai `CancellationTokenSource` đều nằm trong `using` | 6 |

| Phân biệt được bên gọi huỷ (ném lên) với quá hạn (tính là thất bại) bằng mệnh đề `when` | 6 |

<summary><strong>Lời giải — Bài 2</strong></summary>

`Crm.Lab/Notifications.cs`:

```csharp
using Microsoft.Extensions.Logging;

namespace Crm.Lab;

public interface INotifier
{
    string Channel { get; }
    Task SendAsync(int customerId, string message, CancellationToken ct);
}

// Bài 2 — gửi qua mọi kênh song song, có hạn chung
public class CustomerNotificationService(
    IEnumerable<INotifier> notifiers,
    ILogger<CustomerNotificationService> logger,
    TimeSpan? timeout = null)
{
    private readonly TimeSpan _timeout = timeout ?? TimeSpan.FromSeconds(5);

    public async Task<int> SendToAllChannelsAsync(int customerId, string message, CancellationToken ct = default)
    {
        using var timeoutCts = new CancellationTokenSource(_timeout);
        using var linkedCts = CancellationTokenSource.CreateLinkedTokenSource(ct, timeoutCts.Token);

        var results = await Task.WhenAll(
            notifiers.Select(n => SendOneAsync(n, customerId, message, linkedCts.Token, ct)));

        return results.Count(ok => ok);
    }

    private async Task<bool> SendOneAsync(
        INotifier notifier, int customerId, string message,
        CancellationToken linkedToken, CancellationToken callerToken)
    {
        try
        {
            await notifier.SendAsync(customerId, message, linkedToken);
            return true;
        }
        catch (OperationCanceledException) when (!callerToken.IsCancellationRequested)
        {
            // Hết hạn do ta đặt ra: là lỗi của kênh này, ghi log và đi tiếp
            logger.LogWarning("Kênh {Channel} quá {Timeout} giây", notifier.Channel, _timeout.TotalSeconds);
            return false;
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            logger.LogError(ex, "Kênh {Channel} gửi thất bại", notifier.Channel);
            return false;
        }
        // Bên gọi huỷ: OperationCanceledException bay lên, không bị nuốt
    }
}
```

```csharp
    {

            [new OkNotifier("email"), new HangingNotifier()],

            timeout: TimeSpan.FromSeconds(10));

```

Điểm mấu chốt nằm ở hai mệnh đề `when`:

- `catch (OperationCanceledException) when (!callerToken.IsCancellationRequested)`: token nối bị huỷ mà bên gọi **không** huỷ, nghĩa là hạn của ta đã hết. Đó là lỗi của kênh, ghi log và trả `false`.
- Khi bên gọi huỷ, không khối `catch` nào khớp, ngoại lệ bay lên, `Task.WhenAll` kết thúc ở trạng thái bị huỷ và `await` ném `OperationCanceledException` cho bên gọi. Đúng quy tắc "không nuốt tín hiệu huỷ" của [bài 6.4](6.4-cancellationtoken.md).

Mỗi kênh tự bắt lỗi của nó (mẫu "thu thập kết quả từng phần" ở [bài 6.5](6.5-task-parallel-library.md)), nên `WhenAll` không bao giờ mất ngoại lệ. Kết quả trên .NET 10: cả 9 test của ba bài lab xanh, bộ test chạy khoảng 1 giây.

#### Bài 3 — Xuất khách hàng ra CSV bằng `IAsyncEnumerable<T>` (Khá, 25 điểm)

```csharp
public record CustomerExportDto(int Id, string Name, string Email, DateTime CreatedAt);
public record CustomerExportCriteria(DateTime? FromDate, DateTime? ToDate, bool OnlyActive);

public class CustomerExportService(CrmDbContext db)
{
    // Stream khách hàng từ database theo điều kiện lọc, không nạp hết vào RAM
    public IAsyncEnumerable<CustomerExportDto> StreamAsync(CustomerExportCriteria criteria, CancellationToken ct = default)
        => throw new NotImplementedException();

    // Dùng StreamAsync để ghi file CSV từng dòng; trả về số dòng dữ liệu đã ghi
    public Task<int> ExportToCsvAsync(string filePath, CustomerExportCriteria criteria, CancellationToken ct = default)
        => throw new NotImplementedException();
}
```

Yêu cầu:

1. `StreamAsync` là async iterator (`async IAsyncEnumerable<T>` + `yield return`), áp điều kiện lọc của `criteria` **trong truy vấn** (không lọc sau khi đã nạp), dùng `AsNoTracking()` và `AsAsyncEnumerable()`.
2. Tham số token có `[EnumeratorCancellation]` để huỷ có tác dụng.
3. `ExportToCsvAsync` dùng `await foreach` để ghi từng dòng; trường có dấu phẩy phải được bọc trong nháy kép.
4. Test: xuất với `OnlyActive`, lọc theo khoảng ngày, và huỷ giữa chừng thì ném `OperationCanceledException`.

**Tiêu chí chấm:**

| Tiêu chí | Điểm |
|---|---|
| `StreamAsync` lọc trong truy vấn, `AsNoTracking`, trả dần bằng `yield return` | 8 |
| `[EnumeratorCancellation]` có mặt và test huỷ giữa chừng chứng minh vòng lặp dừng sau đúng một dòng | 7 |
| `ExportToCsvAsync` dùng `await using` cho `StreamWriter`, ghi từng dòng, xử lý dấu phẩy | 6 |

```csharp
using System.Runtime.CompilerServices;
using Microsoft.EntityFrameworkCore;

namespace Crm.Lab;

public record CustomerExportDto(int Id, string Name, string Email, DateTime CreatedAt);
public record CustomerExportCriteria(DateTime? FromDate, DateTime? ToDate, bool OnlyActive);

// Bài 3 — stream khách hàng, không nạp hết vào RAM
public class CustomerExportService(CrmDbContext db)
{
    public async IAsyncEnumerable<CustomerExportDto> StreamAsync(
        CustomerExportCriteria criteria,
        [EnumeratorCancellation] CancellationToken ct = default)
    {
        var query = db.Customers.AsNoTracking();
        if (criteria.OnlyActive) query = query.Where(c => c.IsActive);
        if (criteria.FromDate is { } from) query = query.Where(c => c.CreatedAt >= from);
        if (criteria.ToDate is { } to) query = query.Where(c => c.CreatedAt < to);

        var rows = query
            .OrderBy(c => c.Id)
            .Select(c => new CustomerExportDto(c.Id, c.Name, c.Email, c.CreatedAt))
            .AsAsyncEnumerable();

        await foreach (var row in rows.WithCancellation(ct))
            yield return row;
    }

    public async Task<int> ExportToCsvAsync(string filePath, CustomerExportCriteria criteria, CancellationToken ct = default)
    {
        await using var writer = new StreamWriter(filePath);
        await writer.WriteLineAsync("Id,Name,Email,CreatedAt");

        int count = 0;
        await foreach (var c in StreamAsync(criteria, ct))
        {
            await writer.WriteLineAsync($"{c.Id},{Csv(c.Name)},{Csv(c.Email)},{c.CreatedAt:O}");
            count++;
        }
        return count;
    }

    // Trường có dấu phẩy, nháy kép hoặc xuống dòng thì bọc trong nháy kép
    private static string Csv(string value)
        => value.IndexOfAny([',', '"', '\n']) >= 0 ? $"\"{value.Replace("\"", "\"\"")}\"" : value;
}
```

```csharp
    }

    [Fact]
    public async Task StreamAsync_CancelMidway_Throws()
    {
        using var f = new SqliteFixture();

        var read = 0;

        await Assert.ThrowsAnyAsync<OperationCanceledException>(async () =>
        {
            await foreach (var _ in new CustomerExportService(f.Db)
                .StreamAsync(new CustomerExportCriteria(null, null, false), cts.Token))
```

Ba chi tiết:

1. **Lọc trong truy vấn.** Các `Where` được nối vào `IQueryable` trước khi gọi `AsAsyncEnumerable()`, nên EF Core dịch chúng thành `WHERE` trong SQL. Lọc sau khi nạp là kéo cả bảng về.
2. **`[EnumeratorCancellation]`.** Thiếu nó, token truyền qua `WithCancellation` từ bên ngoài sẽ không tới được vòng lặp bên trong ([bài 6.6](6.6-async-patterns.md)). Test huỷ giữa chừng chứng minh vòng lặp dừng ngay sau dòng đầu.
3. **`ExportToCsvAsync` không bao giờ giữ cả danh sách.** Bộ nhớ của nó không phụ thuộc số khách hàng; số đo ở bài tập 1 của [bài 6.6](6.6-async-patterns.md): 23 MB so với 168 MB cho 200.000 dòng.
