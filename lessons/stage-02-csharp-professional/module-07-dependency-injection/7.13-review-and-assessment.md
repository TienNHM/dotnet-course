### 7.13.2 — Phần A: Quiz (20 điểm, mỗi câu 2 điểm)

**Câu 1.** `AddDbContext<CrmDbContext>()` đăng ký `CrmDbContext` với lifetime nào, và vì sao đó là lựa chọn đúng cho ứng dụng web?
A. Singleton, để dùng chung kết nối
B. Scoped, để mỗi request có một change tracker riêng
C. Transient, để mỗi repository có context riêng
D. Tuỳ provider database

<details>
<summary>Đáp án câu 1</summary>

**B.** Mỗi request một `DbContext`: các repository trong cùng request dùng chung nó nên `SaveChangesAsync` ghi mọi thay đổi trong một lần, và context được dispose khi request kết thúc. Singleton làm change tracker phình mãi và trả dữ liệu cũ; Transient làm các repository trong cùng request không chia sẻ được thay đổi. Xem [bài 7.4](7.4-service-lifetimes.md).

</details>

**Câu 2.** Đoạn code sau in ra gì?

```csharp
var s = new ServiceCollection();
s.AddSingleton<IEmail, SmtpEmail>();
s.AddSingleton<IEmail, SendGridEmail>();
var p = s.BuildServiceProvider();
Console.WriteLine(p.GetRequiredService<IEmail>().GetType().Name);
Console.WriteLine(p.GetServices<IEmail>().Count());
```

A. `SmtpEmail` rồi `1` B. `SendGridEmail` rồi `2` C. `SmtpEmail` rồi `2` D. Ném lỗi vì đăng ký trùng

<details>
<summary>Đáp án câu 2</summary>

**B.** Khi resolve một instance, đăng ký **sau cùng** thắng; `GetServices` trả về **tất cả** theo thứ tự đăng ký. Container không bao giờ báo lỗi vì đăng ký trùng. Xem [bài 7.2](7.2-ioc-container-and-di-container.md).

</details>

**Câu 3.** Captive dependency là gì?
A. Service không được đăng ký
B. Service có lifetime dài giữ tham chiếu tới service có lifetime ngắn hơn, ví dụ Singleton giữ Scoped
C. Hai constructor cùng giải được
D. Vòng phụ thuộc A cần B, B cần A

<details>
<summary>Đáp án câu 3</summary>

**B.** Service bị giam sống theo lifetime của service giữ nó, nên một `DbContext` hay `ITenantContext` vốn chỉ sống một request bị dùng mãi. Xem [bài 7.4](7.4-service-lifetimes.md) và [bài 7.11](7.11-mini-case-study.md).

</details>

**Câu 4.** Ứng dụng có một Singleton nhận một Scoped qua constructor. Chỉ bật `ValidateOnBuild = true`, **không** bật `ValidateScopes`. Điều gì xảy ra lúc khởi động?
A. Ném lỗi "Cannot consume scoped service ... from singleton ..."
B. Không báo lỗi gì
C. Ném lỗi "Unable to resolve service"
D. Container tự đổi Scoped thành Singleton

<details>
<summary>Đáp án câu 4</summary>

**B.** `ValidateOnBuild` chỉ kiểm tra mọi service có dựng được không (bắt thiếu đăng ký). Luật lifetime thuộc về `ValidateScopes`; chỉ khi bật **cả hai** thì captive dependency mới nổ ngay lúc build. Bài 2 của [bài 7.11](7.11-mini-case-study.md) đo điều này trên .NET 10.

</details>

**Câu 5.** Trong `Program.cs` của ứng dụng web .NET 10, bạn gọi `builder.Services.AddScoped<IFoo, Foo>()` **sau** `var app = builder.Build();`. Kết quả?

B. Chạy bình thường, `IFoo` dùng được
C. Ứng dụng ném `InvalidOperationException` ngay tại dòng đó: danh sách đăng ký đã chỉ đọc

<summary>Đáp án câu 5</summary>

**C.** `Build()` khoá `builder.Services`; thông báo là "The service collection cannot be modified because it is read-only." Xem [bài 7.6](7.6-program-cs-and-webapplicationbuilder.md).

</details>

**Câu 6.** Factory `AddSingleton<IReportService>(sp => new ReportService(sp.GetRequiredService<ICustomerRepository>()))`, với `ICustomerRepository` là Scoped. `sp` ở đây là gì?

B. Root provider
C. Một scope mới tạo riêng cho factory
D. `null`

<details>
<summary>Đáp án câu 6</summary>

**B.** Factory của Singleton luôn chạy với root provider. Bật `ValidateScopes` thì lần resolve đầu ném "Cannot resolve scoped service ... from root provider"; tắt kiểm tra thì repository bị giam vĩnh viễn và không bao giờ được dispose. `ValidateOnBuild` không nhìn vào lambda nên không bắt được lúc khởi động. Xem [bài 7.5](7.5-registering-services.md).

</details>

**Câu 7.** Một Singleton muốn đọc `ITenantContext` (Scoped, được middleware gán tenant cho request) nên gọi `scopeFactory.CreateScope()` rồi lấy `ITenantContext` từ scope đó. Nó nhận được gì?

B. Một `ITenantContext` mới, chưa có tenant của request

<summary>Đáp án câu 7</summary>

**B.** `CreateScope()` tạo scope mới, độc lập với scope của request. Với dữ liệu theo request: truyền tham số, đổi service sang Scoped, hoặc đọc `IHttpContextAccessor` trong phương thức. Xem [bài 7.11](7.11-mini-case-study.md).

</details>

**Câu 8.** Service Singleton cần thấy giá trị mới khi `appsettings.json` đổi lúc đang chạy. Tiêm gì?
A. `IOptions<T>` B. `IOptionsSnapshot<T>` C. `IOptionsMonitor<T>` và đọc `CurrentValue` mỗi lần dùng D. `IConfiguration` rồi tự parse

A. Chậm hơn constructor injection

#### Bài 1 — Refactor `CustomerService` sang DI (Dễ, 25 điểm)

Cho lớp dính chặt sau (cùng ý với [bài 7.1](7.1-di-problem-scope.md)):

Yêu cầu:

<summary><strong>Lời giải — Bài 1</strong></summary>

`Crm.Lab/Customers.cs`:

```csharp
using System.Collections.Concurrent;
using Microsoft.Extensions.Logging;

namespace Crm.Lab;

public record Customer(Guid Id, string Name, string Email);
public record CreateCustomerRequest(string Name, string Email);

public interface ICustomerRepository
{
    Task AddAsync(Customer customer, CancellationToken ct = default);
    Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct = default);
    Task<IReadOnlyList<Customer>> GetAllAsync(CancellationToken ct = default);
}

public interface IEmailService
{
    Task SendWelcomeEmailAsync(string email, CancellationToken ct = default);
}

// Lưu trong bộ nhớ: Singleton nên phải an toàn khi nhiều luồng dùng cùng lúc
public sealed class InMemoryCustomerRepository : ICustomerRepository
{
    private readonly ConcurrentDictionary<Guid, Customer> _customers = new();

    public Task AddAsync(Customer customer, CancellationToken ct = default)
    {
        _customers[customer.Id] = customer;
        return Task.CompletedTask;
    }

    public Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct = default)
        => Task.FromResult(_customers.GetValueOrDefault(id));

    public Task<IReadOnlyList<Customer>> GetAllAsync(CancellationToken ct = default)
        => Task.FromResult<IReadOnlyList<Customer>>(_customers.Values.ToList());
}

// Thay cho SMTP thật khi học: chỉ in ra màn hình
public sealed class ConsoleEmailService : IEmailService
{
    public Task SendWelcomeEmailAsync(string email, CancellationToken ct = default)
    {
        Console.WriteLine($"[email] Gửi thư chào mừng tới {email}");
        return Task.CompletedTask;
    }
}

public class CustomerService(
    ICustomerRepository repository,
    IEmailService emailService,
    ILogger<CustomerService> logger)
{
    public async Task<Customer> CreateCustomerAsync(CreateCustomerRequest request, CancellationToken ct = default)
    {
        if (string.IsNullOrWhiteSpace(request.Name))
            throw new ArgumentException("Tên không được rỗng", nameof(request));
        if (!request.Email.Contains('@'))
            throw new ArgumentException("Email không hợp lệ", nameof(request));

        var customer = new Customer(Guid.NewGuid(), request.Name.Trim(), request.Email.Trim());
        await repository.AddAsync(customer, ct);
        await emailService.SendWelcomeEmailAsync(customer.Email, ct);
        logger.LogInformation("Đã tạo khách hàng {CustomerId}", customer.Id);
        return customer;
    }
}
```

`Crm.Lab/Program.cs` (phần Bài 1; Bài 3 thêm vài dòng vào đây):

```csharp
using Crm.Lab;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

var builder = Host.CreateApplicationBuilder(args);

builder.Services.AddSingleton<ICustomerRepository, InMemoryCustomerRepository>();  // giữ dữ liệu: Singleton
builder.Services.AddSingleton<IEmailService, ConsoleEmailService>();              // không trạng thái
builder.Services.AddScoped<CustomerService>();

using var host = builder.Build();

using (var scope = host.Services.CreateScope())
{
    var customers = scope.ServiceProvider.GetRequiredService<CustomerService>();
    var created = await customers.CreateCustomerAsync(new("Nguyễn Văn An", "an@example.com"));
    Console.WriteLine($"Đã tạo: {created.Name} <{created.Email}>");
}
```

Output khi chạy trên .NET 10 (Guid khác mỗi lần; dòng `info:` có thể xen ở vị trí khác vì logger ghi ra màn hình ở luồng nền):

```text
[email] Gửi thư chào mừng tới an@example.com
Đã tạo: Nguyễn Văn An <an@example.com>
info: Crm.Lab.CustomerService[0]
      Đã tạo khách hàng cde7a7b0-63b5-42a1-ab2c-6cdec507935a
```

Vì sao `InMemoryCustomerRepository` là Singleton: nếu đăng ký Scoped, mỗi scope có một `Dictionary` rỗng mới, khách hàng tạo ở request này biến mất ở request sau. Singleton thì nhiều request dùng chung, nên phải là `ConcurrentDictionary` ([bài 7.4](7.4-service-lifetimes.md)).

</details>

`Crm.Lab.Tests/CustomerServiceTests.cs`:

```csharp
using Crm.Lab;
using Microsoft.Extensions.Logging.Abstractions;
using NSubstitute;

namespace Crm.Lab.Tests;

public class CustomerServiceTests
{
    private readonly ICustomerRepository _repository = Substitute.For<ICustomerRepository>();
    private readonly IEmailService _emailService = Substitute.For<IEmailService>();
    private readonly CustomerService _sut;

    public CustomerServiceTests()
        => _sut = new CustomerService(_repository, _emailService, NullLogger<CustomerService>.Instance);

    [Fact]
    public async Task CreateCustomerAsync_ValidRequest_SavesAndSendsWelcomeEmail()
    {
        var request = new CreateCustomerRequest("Nguyễn Văn An", "an@example.com");

        var result = await _sut.CreateCustomerAsync(request);

        Assert.Equal("an@example.com", result.Email);
        await _repository.Received(1).AddAsync(
            Arg.Is<Customer>(c => c.Email == "an@example.com"), Arg.Any<CancellationToken>());
        await _emailService.Received(1).SendWelcomeEmailAsync("an@example.com", Arg.Any<CancellationToken>());
    }

    [Fact]
    public async Task CreateCustomerAsync_InvalidEmail_ThrowsAndDoesNothing()
    {
        var request = new CreateCustomerRequest("An", "khong-co-a-cong");

        await Assert.ThrowsAsync<ArgumentException>(() => _sut.CreateCustomerAsync(request));

        await _repository.DidNotReceiveWithAnyArgs().AddAsync(default!, default);
        await _emailService.DidNotReceiveWithAnyArgs().SendWelcomeEmailAsync(default!, default);
    }
}
```

`DidNotReceiveWithAnyArgs()` khẳng định phương thức **không** được gọi với bất kỳ tham số nào; các giá trị `default!` chỉ để cú pháp hợp lệ.

`Crm.Lab.Tests/LifetimeTests.cs`:

```csharp
using Microsoft.Extensions.DependencyInjection;

namespace Crm.Lab.Tests;

public class LifetimeTests
{
    private sealed class ScopedThing;
    private sealed class TransientThing;

    [Fact]
    public void Scoped_SameInsideScope_DifferentAcrossScopes_TransientAlwaysNew()
    {
        var services = new ServiceCollection();
        services.AddScoped<ScopedThing>();
        services.AddTransient<TransientThing>();
        using var root = services.BuildServiceProvider(new ServiceProviderOptions { ValidateScopes = true });

        using var scope1 = root.CreateScope();
        using var scope2 = root.CreateScope();
        var a = scope1.ServiceProvider.GetRequiredService<ScopedThing>();
        var b = scope1.ServiceProvider.GetRequiredService<ScopedThing>();
        var c = scope2.ServiceProvider.GetRequiredService<ScopedThing>();

        Assert.True(ReferenceEquals(a, b));     // cùng scope: cùng instance
        Assert.False(ReferenceEquals(a, c));    // khác scope: khác instance
        Assert.False(ReferenceEquals(
            scope1.ServiceProvider.GetRequiredService<TransientThing>(),
            scope1.ServiceProvider.GetRequiredService<TransientThing>()));   // transient: luôn mới
    }
}
```

Cả ba test xanh trên .NET 10. Để ý test của `CustomerService` không cần container nào: đó chính là lợi ích của constructor injection mà [bài 7.1](7.1-di-problem-scope.md) hứa.

</details>

#### Bài 3 — Options pattern cho `CrmSettings` (Khá, 30 điểm)

Mỗi nhân viên kinh doanh (agent) chỉ được giữ tối đa `MaxLeadsPerAgent` lead đang mở.

1. Tạo lớp `CrmSettings` với hằng `SectionName = "Crm"` và thuộc tính `MaxLeadsPerAgent`, giá trị hợp lệ từ 1 tới 1000. Thêm `"Crm": { "MaxLeadsPerAgent": 50 }` vào `appsettings.json` (đặt `CopyToOutputDirectory` để file được chép khi build).
2. Tạo `ILeadRepository` với `Task<int> CountOpenLeadsAsync(int agentId, CancellationToken ct)` và một bản in-memory trả dữ liệu mẫu.
3. Tạo `LeadService` nhận `ILeadRepository` và `IOptions<CrmSettings>`, có `Task<bool> CanAssignLeadAsync(int agentId, CancellationToken ct)`: trả `true` khi số lead đang mở **nhỏ hơn** hạn mức.
4. Đăng ký Options với `ValidateDataAnnotations()` và `ValidateOnStart()`, gọi `await host.StartAsync()` trước khi dùng service.
5. Viết test: `CanAssignLeadAsync` đúng ở ba trường hợp dưới, bằng và trên hạn mức; và một test chứng minh cấu hình `MaxLeadsPerAgent = 0` làm host không khởi động được.

**Tiêu chí chấm:**

```csharp
using System.ComponentModel.DataAnnotations;
using Microsoft.Extensions.Options;

namespace Crm.Lab;

public sealed class CrmSettings
{
    public const string SectionName = "Crm";

    [Range(1, 1000)]
    public int MaxLeadsPerAgent { get; init; }
}

public interface ILeadRepository
{
    Task<int> CountOpenLeadsAsync(int agentId, CancellationToken ct = default);
}

public sealed class InMemoryLeadRepository : ILeadRepository
{
    public Task<int> CountOpenLeadsAsync(int agentId, CancellationToken ct = default)
        => Task.FromResult(agentId == 1 ? 50 : 3);      // dữ liệu mẫu
}

public class LeadService(ILeadRepository leads, IOptions<CrmSettings> options)
{
    public async Task<bool> CanAssignLeadAsync(int agentId, CancellationToken ct = default)
    {
        var open = await leads.CountOpenLeadsAsync(agentId, ct);
        return open < options.Value.MaxLeadsPerAgent;
    }
}
```

`Crm.Lab.Tests/LeadServiceTests.cs`:

```csharp
using Crm.Lab;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Options;
using NSubstitute;

namespace Crm.Lab.Tests;

public class LeadServiceTests
{
    [Theory]
    [InlineData(2, true)]     // dưới hạn mức
    [InlineData(3, false)]    // đúng bằng hạn mức: không nhận thêm
    [InlineData(4, false)]    // vượt hạn mức
    public async Task CanAssignLeadAsync_ComparesOpenLeadsWithLimit(int openLeads, bool expected)
    {
        var leads = Substitute.For<ILeadRepository>();
        leads.CountOpenLeadsAsync(7, Arg.Any<CancellationToken>()).Returns(openLeads);
        var options = Options.Create(new CrmSettings { MaxLeadsPerAgent = 3 });
        var sut = new LeadService(leads, options);

        Assert.Equal(expected, await sut.CanAssignLeadAsync(7));
    }

    [Fact]
    public async Task InvalidSettings_HostFailsToStart()
    {
        var builder = Host.CreateApplicationBuilder();
        builder.Configuration.AddInMemoryCollection(new Dictionary<string, string?>
        {
            ["Crm:MaxLeadsPerAgent"] = "0",
        });
        builder.Services.AddOptions<CrmSettings>()
            .Bind(builder.Configuration.GetSection(CrmSettings.SectionName))
            .ValidateDataAnnotations()
            .ValidateOnStart();
        using var host = builder.Build();

        var ex = await Assert.ThrowsAsync<OptionsValidationException>(() => host.StartAsync());
        Assert.Contains("MaxLeadsPerAgent", ex.Message);
    }
}
```

`Options.Create(...)` bọc một đối tượng thành `IOptions<T>`: test không cần container hay file cấu hình. Toàn bộ 7 test của ba bài lab xanh trên .NET 10.

**Mở rộng (không chấm điểm):** đổi `IOptions<CrmSettings>` thành `IOptionsMonitor<CrmSettings>`, giữ app chạy (ví dụ thêm `await host.WaitForShutdownAsync();`), sửa `MaxLeadsPerAgent` trong `bin/Debug/net10.0/appsettings.json` và in giá trị trong callback `OnChange` ([bài 7.7](7.7-options-pattern.md)).
